# Sample data for local development

These files feed the seeded demo (`scripts/dev.sh`) and can be uploaded by hand
on the Forensics page. Everything here is synthetic and harmless: addresses come
from the reserved documentation ranges (RFC 5737), domains end in the reserved
`.example`, and "secrets" are fake or published examples.

| File | Try it with | What it shows |
| ---- | ----------- | ------------- |
| `forensics/access.log` | Forensics → read logs (`logscan`) | SQL injection attempts, a path-traversal probe, a Log4Shell lookup string and a web-shell call, with a timeline |
| `forensics/auth.log` | Forensics → read logs (`logscan`) | SSH brute force from one address followed by a successful login |
| `forensics/indicators.txt` | Forensics → match threats (`iocmatch`) | Indicators that match addresses and a domain in `access.log` |
| `forensics/site-backup.zip` | Forensics → add evidence (`triage`) | A WordPress backup with an inert PHP backdoor and PHP in `uploads/`, an `.htaccess` that cloaks crawlers to a spam domain, and `wp-config.php` with fake credentials |
| `apk/northwind-field.apk` | Forensics → add evidence, or `apkscan` | A synthetic Android app: debuggable, allows backup and cleartext traffic, an exported activity, AWS's documented example key, and ECB-mode crypto |
| `authorization-letter.md` | Engagement authorization | The sample letter the demo engagement cites |

The APK is generated by the same encoders the `apkscan` tests use, and a test
checks it still produces its findings. Regenerate it with:

```sh
ARES_WRITE_SAMPLES=1 go test ./internal/modules/apkscan -run TestSampleAPK
```
