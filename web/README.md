# Ares web

The Ares control-plane frontend: a clean, installable PWA for running authorized
engagements. It talks to the Go backend over **ConnectRPC**, using a client
**generated from the same `.proto` files** as the server, so the two cannot
drift.

## Stack

- **Bun** (package manager / runtime), **Vite 8**, **React 19**, **TypeScript 7**
- **Mantine 9.8** components + **Tailwind CSS 4** utility layout
- **TanStack Query** (server state) + **TanStack Router** (type-safe routes)
- **ConnectRPC v2** (`@connectrpc/connect` + `connect-web`), client generated by
  `buf` with `protoc-gen-es`
- **PWA**: installable, offline app shell via a service worker (the control-plane
  API is never cached — operators always see live state)
- **Web worker**: the audit trail is re-verified in the browser, off the main
  thread, recomputing the SHA-256 hash chain exactly as the backend does — so the
  UI shows an *independent* integrity verdict, not just the server's claim

## Develop

```sh
bun install
bun run generate     # regenerate the Connect client from ../proto (needs buf)
bun run dev          # http://localhost:5173 (proxies Connect calls to :8080)
bun run typecheck    # tsc (TypeScript 7) --noEmit
bun run build        # production build + service worker
```

Run the backend alongside it: `go run ./cmd/ares-server` from the repo root. Set
`VITE_ARES_URL` to point at a backend on a different origin.

## Layout

```
src/gen/            generated Connect client (from ../proto)
src/client.ts       the typed ControlPlane client + transport
src/routes/         root layout, engagements list, engagement detail
src/features/       the parts of the engagement screen
src/ui/             shared building blocks (see DESIGN.md)
src/lib/labels.ts   all plain-language wording
src/workers/        audit-verify web worker (independent chain verification)
src/hooks/          useAuditVerification (drives the worker)
```
